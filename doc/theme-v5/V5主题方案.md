# Trime V5 主题方案 · 方块

> 以用户提供的 `ss.trime.yaml`（方块 / linzianxyz / `config_version: "3.0"`）为素材，把前几轮讨论收敛的命名规范落成一份**完整、可校验、可反向降级**的第五代主题文件。
> 不是 RFC、不是改仓库：这是一份具体皮肤从 V3 迁到 V5 的完整实例。

## 3. V5 文件结构：四个区

```
A 未迁移区   height / round_corner / style / preedit / window / tool_bar / liquid_keyboard
             → 与命名无关的视觉、几何、功能开关，逐字保留（含 YAML 锚点）
B 颜色       schemes.<id>.color / pairs / fallback_colors / color_aliases / legacy_colors
C 键         keys.<行为ID> / key_aliases
D 布局       layouts.<场景>.rows / overrides
```

### B 颜色：路径式 `color.<域>.<部件>[.<角色>][.<状态>]`

```yaml
schemes:
  default:
    appearance: light
    color:
      "key.surface":                     "0xFFFDFDFD"
      "key.surface.pressed":             "0xFFC8CCD4"
      "key.surface.modifier":            "0xFFD5D9E0"
      "key.surface.modifier.capsLock":   "0xFFE8F0FE"
      "key.surface.space":               "0xFFF5F6F8"
      "key.surface.action":              "0xFF1A73E9"
      "candidate.comment.content":       "0xFF6C6C70"
```

- 值统一 `"0xAARRGGBB"`（加引号字符串；YAML 里 `#` 是注释符，故不用元书的 `#RRGGBBAA`）。
- 部件词固定 `surface / content / hint / outline / elevation`；状态恒在**末段**，`patch` 一截就到。
- **长路径优先、短路径回退**：`key.surface.space.pressed` 未定义 → 退 `key.surface.space` → 退 `key.surface`。
- 每套 **43 条路径**（原 61 字段），三套路径集合完全一致；`28` 条 `fallback_colors` 转成路径式引用链，值可以是另一个路径名。

`pairs` 替代双向互指，本例 **2 组**：`default↔night`（默认）与 `Spring↔night`。原文件里 night 只认 default，Spring 的深色切换实际落空，V5 用显式配对修好。

`bc1~bc4` 这 10 个位置标签**降为别名**：

| 标签 | 原用途 | V5 路径 | 对应 class |
| --- | --- | --- | --- |
| `bc1`/`tc1`/`baoe`/`taoe` | 第 3 行 Shift | `key.surface.modifier` | `modifier` |
| `bc2`/`tc2` | 退格 / 符号 / 标点 | `key.surface.system` | `system` |
| `bc3`/`tc3` | 空格 | `key.surface.space` | `space` |
| `bc4`/`tc4` | 回车 | `key.surface.action` | `action` |

这正好证明：**按位置分组的色标签，本质就是 `class` 修饰段**。二维布局一改行号，标签全废；class 不动。

### C 键：161 → 23 个行为 ID + 33 条别名

```yaml
keys:
  "key.edit.space":
    class: "space"
    label: ""
    action: { name: "action.text.commit", params: { text: " " } }
  "key.nav.left":
    label: "←"
    action: { name: "action.edit.moveCursor", params: { axis: x, step: char, direction: -1 } }
    repeatable: true
```

- **23 个行为 ID**，`key.<domain>.<name>`，全局一份，与设备 / 方向 / 主题无关。
- **33 条 `key_aliases`**：`Return/Return1/Return2 → key.edit.enter`，`Shift_L_Lock → key.modifier.shift`（差异记 `label` / `states` / `lock`），替身键不再占用行为名空间。
- 动作全部命中仓库 `ActionCatalog.yaml` 的 39 项封闭动词；方向、文本、目标键盘等差异一律降级为 `params`，不造新键名。
- `class` 与 `state` 是按键侧和颜色侧**唯一接缝**，取值来自同一份 `vocabulary.yaml`。

### D 布局：行数组即坐标，每键 0 个坐标

```yaml
layouts:
  "standard26.portrait":
    columns: 10
    unit: 10.0
    rows:
      - [q, w, e, r, t, y, u, i, o, p]
      - [{ gap: 0.5 }, a, s, d, f, g, h, j, k, l]
      - [{ key: "key.modifier.shift", span: 1.4, class: "modifier" }, { gap: 0.1 }, z, x, c, v, b, n, m, { gap: 0.1 }, { key: "key.edit.backspace", span: 1.4, class: "system" }]
      - [{ key: "key.layout.number", span: 1.5, class: "system" }, ",", { key: "key.edit.space", span: 4.5, class: "space" }, ".", { key: "key.edit.enter", span: 1.5, class: "action" }]
  "standard26.landscape":
    columns: 20
    unit: 5.0
    rows: [ ...同一批 ID，不同排布... ]
```

- 数组下标即 X，行容器即 Y；`span` 是**行内相对权重**（1 span = `unit`%），不规则键才写。
- 11 个占位假键转成显式 `{gap: n}`，不再是伪装成键的假对象。
- `when` 承接 `composing` / `long_click` / `swipe_*` 等 13 个触发时机，就地覆盖，替代 `Return1` 这类替身键。
- **横竖屏只换 `layouts` 这一层**：`keys` 与 `schemes` 一个字都不用改。V3 里横屏 `landscape_default` 把 54 个键（含手算 `width: 7.3`）全抄一遍，V5 用同一批 ID 重新排布即可。
- `letter` 布局用 `include: standard26.portrait` 复用，对应 V3 的 `__include`。

## 4. 六条设计决策及依据

1. **继续用 YAML，不换 JSON**。`patch` / `__include` / 注释是同文第三方皮肤的命脉；`ColorTable.resolveRawSource` 已有带环检测的字符串引用链，三层 token 几乎不用写新解析器。
2. **格式 B1**：token 段内 lowerCamel（`capsLock`、`moveCursor`），YAML 结构字段名与 `event` 名保留 snake_case（`ThemeYaml.kt` 的 `YamlNamingStrategy.SnakeCase` + `strictMode=false`，写成 `keyBackColor:` 会被静默丢弃）。
3. **坐标不放进键定义**。坐标属于场景层，用 ID 引用键；否则横竖屏 / 分体 / 平板要复制整套键定义，退回 `Return1` 老病。
4. **`columns` 升格而非另起炉灶**。V3 已有 `columns: 10/20`、`landscape_keyboard`、`ascii_keyboard`、`__include`，V5 把 `columns` 变成网格单位、把一维列表变行数组即可。
5. **版本门 `config_version: "5.0"` + `trime_version: 5`**，旧名整体作为别名层，存量皮肤零改动。
6. **不猜测歧义**。同路径多值、`shadow_color` 一词多义这类，逐字留在 `legacy_colors`（本例 11 个字段），标 `_conflict_paths` 待作者确认，而不是自动挑一个。

## 5. 压缩与无损

| 维度 | V3 | V5 | 说明 |
| --- | ---: | ---: | --- |
| 文件体积 | 69163 B | 57699 B | **−16.6%**（含大量说明注释） |
| 每套颜色字段 | 61 | 43 路径 | 同值合并 43 处，11 处冲突保留 |
| 自定义色标签 | 10 | 0（降为别名） | 由 `class` 决定取色 |
| 明暗关联 | 双向互指（1 处悬空） | 2 组显式 `pairs` | Spring 修好 |
| 行为键（布局引用） | 33 个旧名 | 23 ID + 33 别名 | 替身键合并 |
| 布局表达 | 一维列表 + 手算 width | 4 行数组 + `span` | 每键 0 坐标 |
| 占位假键 | 11 | 0（转 `gap`） | 显式布局元素 |

**信息无损由三件事共同证明**（`validate.py` 第 25 项）：

- 61 × 3 套色值，反向逐字段比对 **全部一致**
- 5 套布局的**每个条目全字段**（click / width / label / 手势 / offset …）逐条一致
- 161 个 `preset_keys` 逐字保留

`build_v5.py` 的 `equivalence_issues` 为 **0 项**。生成器里为此写了 `v3` 迁移提示（替身键精确还原）与 `v3extra`（逐键视觉参数保留），它们是**迁移元数据**，不是身份，后续可归入 `preset_key_style`。

## 7. 已知限制 / 待确认

1. **V5 文件当前 Trime 运行时不认识**。颜色路径别名层、`layouts.rows`、`pairs` 尚未接入 `ColorTable` / `ThemeYaml`；要现在用，请导入 `ss.v3.generated.trime.yaml`。
2. **`trime_version` 取值需拍板**：`doc/naming/legacy-map.yaml` 草案里写的是 `unified: 4`，本方案按「V5」定为 `5`。建议把规范里的 `version_gate` 同步成 5，或把本文件改回 4。
3. **7 个 `key_name` 需回灌词表**：`default / delimiter / down / left / right / tab / up`，已写在 `v5-addendum.yaml`，没有偷偷改仓库规范。
4. **11 个冲突色字段**留在 `legacy_colors`，需作者确认语义后收敛（主要是 `functional_*` 与 `off_key_*` 两套并行机制，以及 `shadow_color` 一词多义）。
5. **`action.params` 尚未参与运行时解析**：`feat/naming-action-verbs` 目前只归一化动词名，带参动词用默认参数。
6. **个别动词是近似映射**：`Color_switch`（`send: PROG_RED`，切换配色）暂归 `action.trime.showSettings`，39 项动词里没有「切换配色」，建议补一个。
7. **`v3extra` 是逐键视觉残留**（offset / `key_text_size` / `functional` 等），后续应归入 `preset_key_style` 的 class 样式，而不是留在布局行。

## 8. 落地顺序建议

1. **立即可用**：导入 `ss.v3.generated.trime.yaml`，验证与原件表现一致。
2. **零风险**：把 `preview.html` 的渲染器思路接进设置页（不改解析语义）。
3. **兼容层**：`trime_version` 分流 + 旧名别名层，`ColorKey.from` / `ColorTable.resolveRawSource` 挂一层归一化。
4. **骨架**：对齐官方 [issue #732](https://github.com/osfans/trime/issues/732) 的 `preset_color` 集中配色 + `preset_key_style` / `class`，从布局移除全部颜色参数。
5. **二维布局**：`columns` 升格为网格单位，`rows` 成为正式布局结构，横竖屏共享 `keys`。
6. **收尾**：`layouts.rows` / `pairs` / `variants` 进解析器，内置主题逐步迁移。
